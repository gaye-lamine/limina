# Requirements: two-model-laws
Status: v1, frozen. Base: `limit-author`, `extract-claims`, `limit-dsl`, `physics-lint` (all unchanged). Additions only to `limina-api`, `limina-extract`, `limina-dsl`; `limina-core` is not modified.

- **R-01** A claim with no built-in limit goes through four steps, each recorded in its `trace` (step, status `done`/`failed`/`skipped`, short factual detail): (i) a model names the established law in one sentence, or answers "no law identified"; (ii) two models write it in the DSL; (iii) a second extraction pass reads the law's parameters from the same text with the same evidence rules; (iv) the engine evaluates it. Failures are reported, never hidden.
- **R-02** The two definitions must pass the DSL checks and are compared on 200 deterministic samples inside their test ranges: relative difference <= 1e-6 on the decisive bound everywhere gives `draft_agreed`; otherwise `draft_disputed` (or `not_authored` when neither passed) and no verdict is produced from it. A draft law never gets `validated_by`.
- **R-03** `POST /v1/curve` returns the bound against one parameter, computed by the limit; `POST /v1/transcribe` reads the text of an image with a vision model; `GET /v1/pipeline` lists what is enabled and the model ids. The key is never logged or returned.
- **R-04** The web app is one screen at 1920x1080 with no page scroll: text or image input with "Analyze"; the trace of the selected claim; claim tabs with the verdict, a plain explanation from engine numbers, a law badge and an explorer whose curves come from `/v1/curve`. Library and "How it works" move to a drawer closed by Escape.
- **AC** Mock tests: agreement, disagreement, one model failing, injection, no law identified, parameter evidence rules, curve, transcription; one `#[ignore]` live test.

## Revision 2026-11-26 (audit of 26/11)
- **R-05** A sample where both definitions fail the same way (outside a domain, a division by zero, a validity condition) is drawn but not compared. Agreement needs at least a quarter of the samples compared (`min_compared`: 50 of 200); otherwise the law is `draft_disputed`. The comparison reports the samples drawn, the samples compared and the ranges sampled (the intersection of the two test ranges).
- **R-06** A law written by AI is never IMPOSSIBLE on its own authority. It is evaluated with the added assumption `draft_formula` (`as_written`: the AI-written bound; `not_validated`: no bound), always left open whatever the request says, so the engine answers CONDITIONAL for a claim beyond the AI-written bound, with the wording "inconsistent with draft limit X if its formula is correct; the formula is an unvalidated draft written by AI, so no IMPOSSIBLE verdict is given". This holds for `POST /v1/analyze`, `POST /v1/evaluate` and the verdicts around the threshold of `POST /v1/solve`. A negative claim against a draft minimum is refused (`DraftNotApplied`), since no bound below 0 exists.
- **R-07** The agreed law is applied only to parameter values inside the ranges where the two definitions were compared (SI units); outside them the claim needs input and the reason names the parameter and the range.
- **AC** DSL tests in `crates/limina-dsl/tests/compare.rs` (undefined everywhere never agrees; a quarter compared; ranges are the intersection; a singular point does not block agreement); API tests in `crates/limina-api/tests/pipeline.rs` and `authoring.rs` (agreed drafts give CONDITIONAL; out-of-range values give no verdict) and the property test of `crates/limina-api/tests/never_impossible.rs` (fixed seed 20261126, 256 cases, 1024 with CI set).
